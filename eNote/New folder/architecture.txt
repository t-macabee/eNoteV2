## Context
You are reviewing a music school management system built with:
- .NET/C# (.NET 10)
- Entity Framework Core
- Clean Architecture with Domain/Application/Infrastructure/API layers
- Actor pattern for authentication/authorization
- CQRS with direct service injection (no MediatR yet)

## Current State Observations

### Architecture Issues to Address
1. **Business Rule Error Handling**: Services throw `BusinessException` for expected outcomes (e.g., "membership inactive", "instrument already locked"). Refactor to use a `Result<T>` pattern:
   - Make happy path explicit
   - Eliminate exception overhead for expected cases
   - Note: This is a significant refactor - evaluate scope

2. **CQRS Implementation**: Controllers currently inject services directly. Consider:
   - Introducing MediatR for command/query separation
   - Enable cross-cutting concerns via pipeline behaviors (logging, validation, caching)
   - Weight benefits vs. added ceremony

3. **Tenant Isolation Vulnerability**: Current implementation uses `actor.GetCurrentStoreIdAsync()` in queries for `MusicStoreId` filtering. Risk of forgetting to apply filters. Implement global query filters in `IModelBuilder`:
   - Auto-scope all queries to current store
   - Prevent accidental cross-tenant data exposure

### Domain Model Improvements
4. **Enum Standardization**: 
   - `EnrollmentStatus` and `LectureStatus` currently use `int` with magic numbers
   - `AttendanceStatus` already has proper enum - apply same pattern consistently
   - Create explicit enum types for all status fields

5. **Money Value Objects**:
   - Fees and prices stored as `decimal` only
   - Create `Money` value object containing `(Amount + Currency)`
   - Prevents currency mixing and makes monetary intent explicit

### Testing Gaps
6. **Integration Test Coverage**:
   - Current tests: Unit + integration tests for services/domain only
   - Add `WebApplicationFactory` tests hitting actual controller endpoints
   - Validate routing, authorization, DTO mapping end-to-end

7. **Test Naming Convention**: Inconsistent `Async` suffix usage. Example: `GetStudentAsync_ResolvesStudentOnlyOnce` doesn't use suffix where others do. Standardize naming pattern.

### Operational Concerns (Pragmatic Additions)
8. **Health Check UI**: Health checks exist but no `/healthz` dashboard or status page. Add visualization.

9. **Request/Response Logging**: No middleware for logging requests/responses. Add Serilog or minimal logging for production debugging.

## Things to Preserve (Do Not Change)
- **IClock abstraction** - Correct pattern, well-executed
- **State machine interface** - Clean separation of concerns
- **Actor pattern** - Solid for auth scoping
- **Repository-less EF Core** - Appropriate for this system size
